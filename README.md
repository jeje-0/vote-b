# IVF 제22차 정기총회 - 법인이사 선출 전자투표

외부 라이브러리 없이 Node.js 기본 모듈만으로 만든 투표 웹앱입니다.
`npm install` 없이 바로 실행됩니다.

## 로컬에서 실행해보기
```
node server.js
```
그 다음 브라우저에서 http://localhost:3000 접속

## 90명에게 보낼 실제 링크 만들기 (무료 호스팅 예시: Render.com)
1. https://render.com 가입 (GitHub 계정으로 가능)
2. 이 폴더(ivf-vote) 전체를 GitHub 저장소에 올리기
3. Render 대시보드 → New → Web Service → 방금 만든 저장소 선택
4. Build Command는 비워두고, Start Command는 `node server.js` 입력
5. 배포가 끝나면 `https://xxxx.onrender.com` 같은 링크가 생성됨 → 이 링크를 90명에게 전달

Render 대신 Railway, Fly.io, 또는 학교/단체에서 쓰는 자체 서버에 올려도 동일하게 동작합니다.

## 투표 데이터가 계속 사라진다면 (중요)
Render 무료 플랜은 서버가 잠들었다 깨어나거나 재배포될 때 파일 시스템이 초기화됩니다.
지금 구조는 기본적으로 `votes.json` 파일에 저장하므로, 이 초기화가 일어나면 그동안 쌓인 투표가 사라집니다.

**영구 저장하려면 Upstash Redis(무료)를 연결하세요:**
1. https://upstash.com 가입 (GitHub 계정으로 가능)
2. 대시보드에서 **Create Database** → Redis 선택 → 이름 아무거나, 지역은 가까운 곳(예: 싱가포르) 선택
3. 생성된 데이터베이스 상세 페이지에서 **REST API** 섹션에 있는 두 값을 복사
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`
4. Render 대시보드 → 해당 서비스 → **Environment** → 위 두 값을 그대로 이름 맞춰서 추가
5. Render가 자동 재배포되면, 이후부터는 재배포/슬립 여부와 무관하게 투표 데이터가 Upstash에 영구 저장됩니다.

환경변수를 설정하지 않으면 기존처럼 `votes.json` 파일 방식으로 동작합니다(로컬 테스트용으로는 그대로 써도 됩니다).

## 관리자 전용 집계 페이지
- 주소: `https://you.onrender.com/admin.html`
- 기본 비밀번호: `ivf2026admin`
- **꼭 바꾸세요**: Render 대시보드 → 해당 서비스 → Environment → `ADMIN_KEY` 라는 이름으로 원하는 비밀번호를 등록하면 그 값으로 바뀝니다. (등록하지 않으면 기본값 그대로 사용됩니다.)
- 투표자 화면(`/`)에는 참여 인원수(진행바)만 보이고, 후보별 찬반 상세 집계는 이 관리자 페이지에서만 볼 수 있습니다.

## 동작 방식
- `public/index.html`, `public/app.js` : 화면(투표 폼 + 실시간 집계)
- `server.js` : 투표 제출을 받아 `votes.json` 파일에 저장하고, 집계 결과를 계산해 내려주는 서버
- `votes.json` : 실제 투표 데이터가 쌓이는 곳 (배포 전 반드시 `[]`로 비워서 시작하세요)

## 집계 방식
- 학생 + 학사 → 하나로 합산
- 이사 → 별도 집계
- 간사 → 별도 집계
- 후보자: 김길동, 이길동, 박길동 (각각 찬성/반대 개별 집계)

## 참고
- 화면은 5초마다 자동으로 최신 집계를 다시 불러옵니다.
- 중복 투표 방지는 같은 브라우저에서 재방문 시 완료 화면을 보여주는 정도이며(브라우저 저장 방식), 완벽한 1인 1표 보장은 아닙니다. 더 엄격하게 막으려면 개인별 고유 링크(토큰) 방식이 필요하니, 필요하시면 추가해 드릴게요.
